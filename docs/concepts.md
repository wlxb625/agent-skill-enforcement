# Core concepts

## Skill

A portable folder containing `SKILL.md`, instructions, scripts, references, templates, or assets.

## Enforced Skill

A Skill that additionally declares execution obligations in `EXECUTION.yaml`.

## Immutable policy

Professional or process rules that adaptive memory and model decisions may not weaken.

## Adaptive policy

User, team, project, or domain preferences that can evolve through validated patches.

## Task policy

Temporary constraints derived for the current request. It disappears or is archived when the task ends.

## Validator

A deterministic checker. It asks “is the artifact structurally or factually valid?”

## Evaluator

A semantic judge. It asks “is the artifact professionally good enough?”

## Gate

A transition authority. It asks “may execution continue?”

## Repair contract

A bounded change request produced by a failed or conditional gate.

## Completion receipt

A machine-readable statement of what ran, what passed, which execution level was used, and what artifact hashes were delivered.
